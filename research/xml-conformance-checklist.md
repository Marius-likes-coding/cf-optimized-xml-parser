# XML 1.0 (5th Ed) + Namespaces 1.0 (3rd Ed) — implementer's checklist for a speed-first non-validating parser

Scope: all section/production numbers below are XML 1.0 Fifth Edition REC 2008-11-26 (`https://www.w3.org/TR/xml/`) and Namespaces 1.0 Third Edition REC 2009-12-08 (`https://www.w3.org/TR/xml-names/`). `WFC` = well-formedness constraint (violation is fatal error, §1.2, §2.1, §5.1: processor MUST detect/report, MUST NOT continue normal processing — https://www.w3.org/TR/xml/#sec-terminology). `VC` = validity constraint (validating processors only; non-validating parser ignores — https://www.w3.org/TR/xml/#proc-types).

Cost legend (for this library's architecture: whole `string`/`Uint8Array` in memory, eager DOM `{name,attrs,children}`, zero-copy slices, whitespace-only text dropped). All costs [inference] unless noted; must be confirmed by workerd benchmark:
- `free` — folds into bytes/chars you already scan; no extra pass or allocation.
- `cheap` — O(1) extra compare / table lookup / hash per token.
- `expensive` — extra pass, per-char function call, allocation, hash table growth, or decoder.

> V8 note: performance lore from before V8 12 (pre-2023, e.g. "avoid try/catch", "hidden-class" micro-rules) is largely outdated for V8 15.1 (2026). No V8-version-specific string-scan claim below is asserted without a benchmark — see Open Questions.

## 3. Encoding detection for byte input (Appendix F)

Normative core (§4.3.3 — https://www.w3.org/TR/xml/#charencoding) [source]: MUST accept UTF-8 + UTF-16; MUST use BOM to discriminate; without external info, non-UTF-8/16 MUST begin with `TextDecl` containing `EncodingDecl` (`EncName ::= [A-Za-z]([A-Za-z0-9._]|-)*`, Latin-only, case-insensitive match SHOULD); fatal on mismatch/illegal bytes/unsupported encoding; `EncodingDecl` values SHOULD use IANA names (`UTF-8, UTF-16, ISO-8859-1…-n, Shift_JIS, EUC-JP, ISO-2022-JP…`).

Non-normative sniff (App. F.1 — https://www.w3.org/TR/xml/#sec-guessing-no-ext-info) [source]: with BOM `00 00 FE FF`=UCS-4BE, `FF FE 00 00`=UCS-4LE, `00 00 FF FE`/`FE FF 00 00`=unusual UCS-4, `FE FF`=UTF-16BE, `FF FE`=UTF-16LE, `EF BB BF`=UTF-8; without BOM `00 00 00 3C…`=UCS-4, `00 3C 00 3F`=UTF-16BE, `3C 00 3F 00`=UTF-16LE, `3C 3F 78 6D` (`<?xm`)=ASCII-compatible 8-bit family (read decl to pick member), `4C 6F A7 94`=EBCDIC. F.2 (https://www.w3.org/TR/xml/#sec-guessing-with-ext-info): external protocol wins; for files use BOM + decl.

What TextDecoder actually supports (WHATWG `names-and-labels` — https://encoding.spec.whatwg.org/#names-and-labels, MDN mirror) [source]: 39 decodable labels — `utf-8`; 28 legacy single-byte (`windows-1252` covers `iso-8859-1/latin1/ascii` as alias, plus `1250–1258, 874, 8859-2…16 minus 1/9/11, koi8-r/u, macintosh…`); `gbk/gb18030/big5/euc-jp/iso-2022-jp/shift_jis/euc-kr/utf-16be/utf-16le/x-user-defined`. NOT supported: `EBCDIC/*, UCS-4, UTF-32, UTF-7, CESU-8, ISO-8859-12, hz-gb-2312, iso-2022-cn/kr` (constructor throws `RangeError`) [source]. `TextEncoder` is UTF-8-only [docs].

Workerd caveat [docs/inference]: Cloudflare docs describe `TextDecoder` as "UTF-8 decoder" (https://developers.cloudflare.com/workers/runtime-apis/encoding/); workerd issues #6038/#6193 (2026) show non-UTF-8 labels (`gbk/big5/shift_jis/euc-kr/utf-16le…`) failing WPT. V8 itself does not implement the Encoding Standard (embedder/ICU does), so "V8 15.1" tells you nothing about label coverage. Feature-detect (`try{new TextDecoder(l)}catch`) — do not assume full WHATWG set on Workers.

Realistic frequency [docs + inference — no XML-only census found]: web-wide (HTML-dominated) W3Techs Sep 2025–2026: UTF-8 ~99%, ISO-8859-1 ~0.8%, windows-1252 ~0.2%, windows-1251/EUC-JP/Shift_JIS/EUC-KR ~0.1% each (https://w3techs.com/technologies/overview/character_encoding). XML is *more* UTF-8-dominant (spec defaults to UTF-8/16 with fatal otherwise; RSS/Atom/SVG/OOXML/sitemaps emit UTF-8; libxml2 built-ins are UTF-8/16/ISO-8859-1/ASCII). Legacy tail worth accepting: UTF-16BE/LE (BOM, .NET/Windows), windows-1252/ISO-8859-1, windows-1251/KOI8-R, Shift_JIS/EUC-JP/ISO-2022-JP, GB2312-as-gbk/GB18030, Big5, EUC-KR. Safe to reject as fatal-unsupported: EBCDIC, UCS-4, UTF-7, HZ — effectively extinct in XML.

Recommended byte path (cheap): sniff 4 bytes → `EF BB BF/FE FF/FF FE` strip → `<?xm`-ASCII fast path (read `encoding="…"` with ASCII-only scan, fail on mismatch) → `new TextDecoder(resolvedOrUtf8, {fatal:true})` → reject EBCDIC/UCS-4 patterns as fatal-unsupported per §4.3.3 allowance. Cost: `free` for UTF-8-no-BOM-no-decl (skip decode entirely if input already string); one decode pass otherwise.

## 4. DOCTYPE / internal subset: what non-validating MUST/MAY do

What the spec says (§5.1 — https://www.w3.org/TR/xml/#proc-types; §4.4 — https://www.w3.org/TR/xml/#entproc; §2.8 — https://www.w3.org/TR/xml/#sec-prolog-dtd) [source]:
- MUST check all WFCs even without DTD, including `WFC: Entity Declared` — *except* when standalone=`no` and the reference appears where an external PE/general entity could have declared it; then MAY skip (pass through) rather than fatal.
- MUST `Include` internal general entities' replacement text; MUST `Bypass` external general entities (notify app, do not expand) unless validating; MAY `Bypass` external PEs; MUST process internal subset for entity/attribute declarations it uses.
- Default attribute values from ATTLIST (internal or external): non-validating MAY but need not supply; standalone=`yes` guarantees none matter.

Defensible choices, cheapest first [inference]:
1. **Reject any document with `<!DOCTYPE` (fatal "DTD not supported")** — non-conformant (a conformant non-validating parser must accept valid/internal-entity docs) but *explicit*, never silently wrong. Defensible for v0/MVP if documented; will fail `valid` xmlconf tests that use internal entities.
2. **Skip-and-ignore (treat internal subset as opaque, expand only the 5 predefined)** — fastest, what fxp/txml/sax do — but **silently wrong** on any doc with `<!ENTITY>` (`&foo;` → literal or fatal depending on C14 choice). Only defensible if paired with fatal-on-unknown-entity (then degrades to choice 1 per-document, not per-syntax).
3. **Parse internal general-entity decls only (`<!ENTITY name "value">`, no PE/external/notation/ELEMENT/ATTLIST), expand synchronously** (parse-xml/saxes-ENTITIES-manual model) — recommended. Cost `cheap` (once per doc, small map). Covers the only internal-subset feature that changes output text. Ignore external IDs (do not fetch — Workers has no sync fetch in parser hot path anyway; fetching is also a security/SSRF surface), ignore ATTLIST defaults, ignore ELEMENT/Notation/CONDITIONAL decls beyond skipping them correctly.

Do not fetch external DTDs/parameter entities/external general entities in the parser [inference]: single-thread CPU limits + no sync I/O make it a latency trap; spec explicitly permits bypassing.

## 5. Namespaces (Namespaces 1.0 3rd Ed)

Extra constraints over XML 1.0 (§7 — https://www.w3.org/TR/xml-names/#Conformance: doc MUST be well-formed XML 1.0 AND element/attr names match `QName`, all other Names match `NCName` = `Name` minus `:` [4] — https://www.w3.org/TR/xml-names/#ns-qualnames) [source]:
- `NSC: Prefix Declared` (§5 [12][13][14][15] — https://www.w3.org/TR/xml-names/#nsc-NSDeclared): prefix other than `xml`/`xmlns` MUST have `xmlns:p="URI"` in scope (start-tag or ancestor). Unbound prefix = namespace-WF error.
- `NSC: No Prefix Undeclaring` (§5 — https://www.w3.org/TR/xml-names/#nsc-NoPrefixUndecl): `xmlns:p=""` forbidden in 1.0 (allowed only in 1.1).
- `NSC: Reserved Prefixes and Namespace Names` (§3 [2] — https://www.w3.org/TR/xml-names/#xmlReserved): `xml` bound by definition to `http://www.w3.org/XML/1998/namespace`, MUST NOT bind to other; other prefixes MUST NOT bind to it; `xmlns` prefix MUST NOT be declared; `xmlns` MUST NOT be default or element prefix; `xml:*` should-be-declared-but-need-not-be.
- `NSC: Attributes Unique` (§6.3 — https://www.w3.org/TR/xml-names/#uniqAttrs): no two attrs with same expanded name (same local + identical-namespace URIs) — so `<x xmlns:n1="U" xmlns:n2="U"><bad n1:a="1" n2:a="2"/></x>` illegal even though raw names differ. URI comparison is byte-identical, case-sensitive, no %-normalization (§2.3 — https://www.w3.org/TR/xml-names/#NSNameComparison).
- Scoping (§6.1–§6.2 — https://www.w3.org/TR/xml-names/#scoping-defaulting): prefix scope = declaring start-tag through matching end-tag (minus inner re-declarations); default `xmlns="U"` applies to unprefixed *elements* only, never to unprefixed *attributes*; `xmlns=""` unsets default. Processor MUST act on declarations (§2.1, §8 — https://www.w3.org/TR/xml-names/#ProcessorConformance; not required to check that namespace names are valid URIs).

Cost of resolving vs raw [inference]:
- **Raw qualified names (no resolution)**: `free` — `:` is already `NameChar`; store slice. What fxp/txml/parse-xml do.
- **Well-formedness checks only (bound-prefix + reserved + dup-expanded)**: `cheap–expensive` — needs per-element scope stack of prefix→URI bindings + per-tag expanded-name dedup (string compares of URIs, not just names). URI-compare cost is proportional to URI length, paid per prefixed attribute.
- **Full resolution (expose `{uri, local}` per node)**: `expensive` — allocates resolved strings/objects per element/attribute, defeating zero-copy; URI slices kept alive anyway but expanded pairs multiply output-tree size. Only pay if the API promises namespace-aware output.

Recommendation: ship namespace-unaware first (raw `name` slice, document it), add opt-in `xmlns:true`-style strict mode (sax-js/saxes pattern) later. If resolving, intern namespace URIs per depth (same URI string reused, not re-sliced) to cap memory.

## 6. XML 1.1 differences worth knowing

Concrete deltas (XML 1.1 2nd Ed — https://www.w3.org/TR/xml11/ vs XML 1.0 5th Ed) [source]:
- `Char` widened: 1.1 allows C0/C1 (`#x1–#xD7FF` almost all) but new `RestrictedChar ::= [#x1-#x8]|[#xB-#xC]|[#xE-#x1F]|[#x7F-#x84]|[#x86-#x9F]` MUST appear only as `&#...;`, never literally (except `#x85`); `#x0` forbidden both (§2.2/§4.1 + https://www.w3.org/XML/2007/08/xml1011.html).
- EOL adds `NEL #x85` and `LSEP #x2028`: `#xD#x85→#xA, #x85→#xA, #x2028→#xA` (§2.11); literal `#x85/#x2028` in XML/Text decl = fatal.
- `XMLDecl` with `version="1.1"` REQUIRED (1.0: optional, `SHOULD`); `VersionNum ::= '1.1'`; 1.0 processors treat `1.x` as 1.0, 1.1 processors SHOULD accept 1.0; higher-version external entity = not-wf (§2.8/§4.3.4).
- `NameStartChar` philosophy flipped (forbidden-unless-allowed → allowed-unless-forbidden) — but 1.0 5th Ed erratum E09 back-ported the open ranges, so 1.0-5e and 1.1 grammars now look identical (https://www.w3.org/XML/2008/02/xml10_5th_edition_background.html) [source]. Remaining name tests differ only vs 1.0 ≤4th Ed (`EDITION="1 2 3 4"` xmlconf tests).
- New §2.13 normalization checks (SHOULD-level, report-only, never WF errors; non-validating ignores unread externals).
- Namespaces 1.1 side-effect: `xmlns:p=""` undeclaration allowed (forbidden in 1.0).

How common [docs/inference]: rare / effectively deprecated. Wikipedia: "not very widely implemented, recommended only for those who need its unique features". Browsers reject `version="1.1"` (Firefox "not well-formed", Chrome/Safari "Unsupported version '1.1'"); expat is 1.0-only ("little demand in 15 years", libexpat#378); libxml2 warns; EPUB mandates 1.0. Only notable producer: Jenkins `config.xml` (`version="1.1"` since 2017). Action: **reject `version="1.1"` explicitly** (fatal "XML 1.1 not supported") — conformant for a 1.0 processor, one `cheap` check; do not pay NEL/LSEP/RestrictedChar costs in the hot loop.

## 7. Cross-cutting: wrong-output vs lenient (summary)

- **Silently wrong if skipped**: C2 (nesting), C4 (dup attrs — data loss), C7/C13/C14 (entity/char-ref handling), N1/N2/N4 (EOL/attr/BOM — stray `\r`/`\t`/`\uFEFF` in output), C10-unterminated (swallows doc), §4-choice-2 with pass-through entities.
- **Lenient-only (accepts invalid, output fine on valid input)**: C1, C3, C5, C6, C8, C9, C11, C12, C15-grammar, C16, namespace WFCs (if documented unaware), XML 1.1 rejection.
- Speed-first rule of thumb [inference]: keep every `free`/`cheap` check (C1–C11, C13–C15-skip, N1–N4, version gate); defer or flag-gate only C12 per-char Char validation and full namespace resolution — the two genuinely `expensive` items — plus full DTD grammar.

## 8. W3C XML Conformance Test Suite (xmlconf)

- **Latest**: `20130923` (minor corrections; 2008 releases added 5th-Ed tests + `EDITION` attr). Downloads [source] (https://www.w3.org/XML/Test/): `xmlts20130923.zip` / `.tar` / `.tar.gz` (note: `.tar.gz` is actually uncompressed tar — known bug), report `xmlconf-20130923.html`, FAQ `faq.html`, process `XMLConformanceTS-Process-20031210.html`. Origins: OASIS/NIST (James Clark `xmltest`, Fuji Xerox, Sun, IBM) → W3C. No maintained successor; W3C CVS dead; community mirror `lddubeau/xml-conformance-suite` (archived, +JS harness) is convenience only — canonical is `w3.org/XML/Test`.
- **Structure** [source] (`testcases.dtd` + `xmlconf.xml`): root catalog of external entities (`<!ENTITY sun-valid SYSTEM "sun/sun-valid.xml">…`), `<TESTCASES PROFILE=… xml:base="sun/">`, full path = `base` + `TEST/@URI`. Leaf catalogs: `sun/sun-{valid,invalid,not-wf,error}.xml`, `xmltest/xmltest.xml`, `japanese/japanese.xml`, `oasis/oasis.xml`, `ibm/ibm_oasis_{valid,invalid,not-wf}.xml`, `ibm/xml-1.1/…`, `eduni/xml-1.1/xml11.xml`, `eduni/errata-{2e,3e,4e}/`, `eduni/namespaces/{1.0,1.1}/rmt-ns*.xml`. ~2000+ files. Example: `<TEST URI="valid/sa01.xml" ID="sa01" TYPE="valid" SECTIONS="2.9 [32]" OUTPUT="valid/out/sa01.xml">…</TEST>`.
- **Attributes** (`testcases.dtd` comments normative): `TYPE="valid|invalid|not-wf|error"` + `SECTIONS` (spec §, e.g. `2.8`, `3.2.2 [51]`) + `URI` + `ID` required; `ENTITIES="none|parameter|general|both"` (default `none`); `RECOMMENDATION="XML1.0|XML1.1|NS1.0|…"` (default `XML1.0`); `VERSION="1.0|1.1"`; `NAMESPACE="yes|no"` (default `yes`; `no` = colon used non-namespace way); `EDITION="1 2 3 4"` vs `"5"` (absent = all; added 2008 for E09 name-char change); `OUTPUT`/`OUTPUT3` = canonical forms for `valid` tests.
- **License** [source]: historic suite under **W3C Software License (19980720)** per `faq.html` + process doc; individual files carry Sun/OASIS headers. Do NOT retro-apply the 2023 dual BSD/test-suite scheme (https://www.w3.org/copyright/test-suites-licenses/ says it doesn't affect existing suites). Vendoring = preserve notices + link original.
- **JS harness**: unzip; load leaf catalogs directly (avoids XXE/PE expansion of parsing `xmlconf.xml` itself); for each TEST resolve `base+URI`; skip `VERSION==1.1`, `EDITION`-mismatch, `NAMESPACE==no` (if ns-aware), `ENTITIES!=none` (if you don't read externals). Oracle for **non-validating** parser [source] (DTD comment + `xmlconf-20020606` matrix): `valid` → must accept; `invalid` → must **accept** (validity errors are validating-only); `not-wf` → must **reject**, except `ENTITIES!=none` without external reading → accept allowed; `error` → either way conforms. Minimal: `try{parse(file)}catch{assert(TYPE=='not-wf'||TYPE=='error')}`; ignore `OUTPUT*` unless testing infoset/canonicalization.

## Actionable rules for the parser

- Fold EOL (`\r\n`, `\r` → `\n`) into the scanner; never pre-`replace()` the input.
- Enforce: single root, tag-stack match, dup-attr (linear for small tags), no-`<`-in-attr, no-`]]>`-in-text, comment `--`/`--->`, PI `xml`-reservation + `?>`, CDATA termination, decl position/grammar, char/entity-ref grammar + `Legal Character` + unknown-entity fatal, `xmlns=""`-style basics only if ns-aware.
- Normalize: attr `9/A/D` → space; expand the 5 predefined + internal generals (+ char-refs with range check); strip one leading BOM.
- Bytes: 4-byte sniff → ASCII `<?xm` fast path → `TextDecoder(label,{fatal:true})` after feature-detect; fatal on EBCDIC/UCS-4/unknown labels.
- DOCTYPE: bracket-aware skip + root-name check; parse `<!ENTITY name "value">` internal generals only; never fetch externals; fatal on unknown entities (no silent pass-through).
- Stay namespace-unaware (raw slices) for v1; add opt-in strict ns mode later; intern any resolved URIs.
- Reject `version="1.1"` explicitly; ignore all VCs; document whitespace-drop + `xml:space`/`xml:lang` non-support.
- Gate only two things behind flags/omission: per-char `Char`-production validation (C12) and full DTD grammar.
